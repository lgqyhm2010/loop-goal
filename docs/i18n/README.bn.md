# loop-goal

**দীর্ঘ কাজ** নির্ভরযোগ্যভাবে চালানোর জন্য একটি শৃঙ্খলা স্কিল — এমন কাজ যা
হয় কোনো সময়সূচি অনুযায়ী পুনরাবৃত্ত হয় (**লুপ**) অথবা কোনো লক্ষ্য পূরণ
না হওয়া পর্যন্ত চলে (**লক্ষ্য**)।

## ইনস্টল

[`skills`](https://github.com/vercel-labs/skills) CLI দিয়ে এটি যোগ করুন —
কোনো ক্লোন নয়, কোনো ম্যানুয়াল কপি নয়:

```bash
# বর্তমান প্রকল্পে → .claude/skills/
npx skills add lgqyhm2010/loop-goal

# প্রতিটি প্রকল্পের জন্য → ~/.claude/skills/
npx skills add lgqyhm2010/loop-goal -g
```

`skills` রিপোর মূলে `SKILL.md` খুঁজে নেয় এবং সেটি (সেই সঙ্গে
`templates/`) আপনার skills ডিরেক্টরিতে রেখে দেয়। ইন্টারঅ্যাক্টিভ ছাড়াই
ইনস্টল করতে `-a claude-code -y` যোগ করুন।

হাতে করতে চান? `SKILL.md` এবং `templates/` কপি করে
`.claude/skills/loop-goal/`-এ রাখুন।

একবার ইনস্টল হয়ে গেলে, শুধু একটি লুপিং বা শেষ-না-হওয়া-পর্যন্ত-চলা কাজ বর্ণনা
করুন — স্কিলটি নিজে থেকেই ট্রিগার হয় ([কখন এটি ট্রিগার হয়](#কখন-এটি-ট্রিগার-হয়) দেখুন)।

## সমস্যাটি

দীর্ঘ সময় ধরে চলা এজেন্ট কাজ তিনটি নীরব উপায়ে ব্যর্থ হয়:

1. **হারিয়ে যাওয়া অগ্রগতি** — কথোপকথনের কনটেক্সট কমপ্যাক্ট হয়ে যায় এবং
   এজেন্ট ভুলে যায় সে ইতিমধ্যে কী করেছে।
2. **দূষিত কনটেক্সট** — টুলের আউটপুট একের পর এক পুনরাবৃত্তি জুড়ে জমতে থাকে,
   যা দীর্ঘ রানে যুক্তিবিচারকে দুর্বল করে দেয়।
3. **কোনো প্রস্থান নেই** — লিখিত থামার শর্ত ছাড়া একটি লুপ চিরকাল চলতে থাকে।

সমাধানগুলো সুপরিচিত (একটি ফাইলে চেকপয়েন্ট করা, প্রতি পুনরাবৃত্তিতে কনটেক্সট
বিচ্ছিন্ন করা, প্রস্থানের শর্ত লিখে রাখা)। সমস্যা হলো এগুলো নির্ভর করে
এজেন্টের সেগুলো করার কথা *মনে রাখা*র উপর — এবং দীর্ঘ রানে শৃঙ্খলা শিথিল হয়ে
যায়। এই স্কিল তিনটি সমাধানকে বলবৎযোগ্য নিয়মে রূপান্তরিত করে।

## এটি যা করে

আহ্বান করা হলে, স্কিলটি:

1. **মোড শনাক্ত করে** — LOOP (সময়-চালিত, পুনরাবৃত্ত) বনাম GOAL
   (ফলাফল-চালিত, শেষ-না-হওয়া-পর্যন্ত-চলা)।
2. **একটি চেকপয়েন্ট ফাইল বাধ্যতামূলক করে** — `.loopgoal/state.json` একক
   পুনরুদ্ধারযোগ্য স্টেট ধারণ করে; git কমিট ইতিহাস ধারণ করে।
3. **ছয়টি নিয়ম বলবৎ করে** — একটি সুস্পষ্ট প্রস্থান শর্ত দিয়ে init করা, প্রতিটি
   পুনরাবৃত্তি একটি নতুন সাবএজেন্টে চালানো (কনটেক্সট বিচ্ছিন্নকরণ), একটি
   নির্দিষ্ট ক্রমে চেকপয়েন্ট করা, রিজিউমে যাচাই করা, সিদ্ধান্ত লগ করা, পরিচ্ছন্নভাবে
   প্রস্থান করা।

এটি **বিশুদ্ধ শৃঙ্খলা**: এটি কোনো কোড লেখে না, কোনো কমান্ড চালায় না, এবং
`/loop` বা `/schedule`-কে মোড়ায় না — এটি সীমাবদ্ধ করে *কীভাবে* আপনি সেগুলো চালান।

## কখন এটি ট্রিগার হয়

"loop", "goal", "keep running", "run in a loop", "until X",
"run autonomously"-এর মতো বাক্যাংশ — অথবা এদের চীনা প্রতিরূপ "持续做", "每隔", "循环跑",
"直到…为止", "自主跑", "跑个 loop" — অথবা একটি সুস্পষ্ট "use the loop-goal skill"।

## স্বয়ংসম্পূর্ণ

যেকোনো প্রকল্পে কাজ করে। এটি কেবল বিল্ট-ইন টুল (`Agent`, git)
এবং হার্নেস প্রক্রিয়ার (`/loop`, `ScheduleWakeup`) উপর নির্ভর করে। superpowers
প্লাগইন একটি ঐচ্ছিক সঙ্গী, কখনোই আবশ্যিক নয়।

## ফাইল

- `SKILL.md` — স্কিলটি নিজেই: মোড শনাক্তকরণ, চেকপয়েন্ট ফরম্যাট,
  ছয়টি নিয়ম।
- `DESIGN.md` — ডিজাইনের যুক্তি এবং সিদ্ধান্ত।
- `templates/state.json` — চেকপয়েন্ট কঙ্কাল, নিয়ম R1 দ্বারা একটি
  প্রকল্পে কপি করা হয়।
