# loop-goal

Скилл дисциплины для надёжного выполнения **длительных задач** — задач,
которые либо повторяются по расписанию (**циклы**, loops), либо
выполняются до достижения цели (**цели**, goals).

## Установка

loop-goal — это единый `SKILL.md` в `skills/loop-goal/`. Выберите свой инструмент
ниже — он устанавливается в Claude Code, Codex и GitHub Copilot.

### Быстрая установка (все три сразу)

CLI [`skills`](https://github.com/vercel-labs/skills) устанавливает скилл —
без клонирования, без ручного копирования:

```bash
npx skills add lgqyhm2010/loop-goal -a claude-code -a codex -a github-copilot -y
```

Уберите любую ненужную цель `-a …`. Добавьте `-g`, чтобы установить скилл для
каждого проекта, а не только для текущего.

### Claude Code

- **Как скилл:** `npx skills add lgqyhm2010/loop-goal -a claude-code` (`-g` для глобальной установки)
- **Как плагин:** в Claude Code выполните `/plugin marketplace add lgqyhm2010/loop-goal`,
  затем `/plugin install loop-goal@lgqyhm2010`
- **Вручную:** скопируйте `skills/loop-goal/` в `.claude/skills/`

### OpenAI Codex

- **Как скилл:** `npx skills add lgqyhm2010/loop-goal -a codex` — устанавливается в
  `.agents/skills/loop-goal/`. Рекомендуется установка на уровне проекта.
- **Всегда активно:** скопируйте указатель из [`AGENTS.md`](AGENTS.md) в `AGENTS.md`
  вашего собственного репозитория (или в `~/.codex/AGENTS.md`), чтобы дисциплина
  загружалась всегда.

### GitHub Copilot

- **Как скилл:** `npx skills add lgqyhm2010/loop-goal -a github-copilot` — устанавливается
  в `.agents/skills/loop-goal/`.
- **Всегда активно (рекомендуется):** скопируйте указатель из
  [`.github/copilot-instructions.md`](.github/copilot-instructions.md) в
  `.github/copilot-instructions.md` вашего собственного репозитория.

> **Примечания.** Для Codex предпочитайте установку на уровне проекта или путь через
> `AGENTS.md` — глобальный путь CLI (`-g`) (`~/.codex/skills/`) может не совпадать с
> тем местом, откуда Codex читает глобальные скиллы. Для Copilot путь через
> `.github/copilot-instructions.md` — самый надёжный способ поддерживать дисциплину
> всегда активной.

После установки просто опишите циклическую задачу или задачу «выполнять
до завершения» — скилл срабатывает сам (см. [Когда он срабатывает](#когда-он-срабатывает)).

## Проблема

Длительные задачи агента дают сбой тремя незаметными способами:

1. **Потеря прогресса** — контекст диалога сжимается, и агент забывает,
   что уже сделал.
2. **Загрязнённый контекст** — вывод инструментов накапливается от
   итерации к итерации, ухудшая рассуждения на длинной дистанции.
3. **Отсутствие выхода** — цикл без записанного условия остановки
   работает вечно.

Решения хорошо известны (сохранять контрольную точку в файл,
изолировать контекст для каждой итерации, записать условие выхода).
Проблема в том, что они полагаются на то, что агент *не забудет* их
выполнить, — а на длинной дистанции дисциплина размывается. Этот скилл
превращает три решения в принудительно применяемые правила.

## Что он делает

При вызове скилл:

1. **Определяет режим** — LOOP (управляемый временем, повторяющийся) или
   GOAL (управляемый результатом, выполняемый до завершения).
2. **Обязывает использовать файл контрольной точки** — `.loopgoal/state.json`
   хранит единственное восстанавливаемое состояние; коммиты git хранят
   историю.
3. **Применяет семь правил** — инициализация с явным условием выхода,
   выполнение каждой итерации в свежем субагенте (изоляция контекста),
   сохранение контрольной точки в фиксированном порядке, проверка при
   возобновлении, логирование решений, аккуратный выход, и вынесение фазы
   в инструмент `Workflow`, когда она разветвляется на ≥ 4 независимых
   параллельных единиц.

Это **чистая дисциплина**: он не пишет код, не запускает команды и не
оборачивает `/loop` или `/schedule` — он ограничивает то, *как* вы их
запускаете.

## Когда он срабатывает

Фразы вроде "loop", "goal", "keep running", "run in a loop", "until X",
"run autonomously" — или их китайские эквиваленты "持续做", "每隔", "循环跑",
"直到…为止", "自主跑", "跑个 loop" — либо явное "use the loop-goal skill".

## Самодостаточность

Работает в любом проекте. Зависит только от встроенных инструментов
(`Agent`, git) и механизмов харнесса (`/loop`, `ScheduleWakeup`). Плагин
superpowers — необязательный компаньон, но никогда не требование.

## Файлы

- `skills/loop-goal/SKILL.md` — сам скилл: определение режима, формат
  контрольной точки, семь правил.
- `skills/loop-goal/templates/state.json` — скелет контрольной точки,
  копируемый в проект правилом R1.
- `.claude-plugin/` — манифесты плагина и marketplace для Claude Code.
- `AGENTS.md`, `.github/copilot-instructions.md` — минимальные всегда активные
  указатели для Codex и Copilot.
- `DESIGN.md` — обоснование дизайна и принятые решения.
