# loop-goal

**लंबे कार्यों** (long tasks) को भरोसेमंद ढंग से चलाने के लिए एक अनुशासन (discipline) स्किल — ऐसे कार्य जो
या तो किसी शेड्यूल पर दोहराए जाते हैं (**लूप**) या किसी लक्ष्य के पूरा होने तक चलते हैं
(**लक्ष्य**)।

## इंस्टॉल करें

इसे [`skills`](https://github.com/vercel-labs/skills) CLI से जोड़ें —
न क्लोन, न मैन्युअल कॉपी:

```bash
# मौजूदा प्रोजेक्ट में → .claude/skills/
npx skills add lgqyhm2010/loop-goal

# हर प्रोजेक्ट के लिए → ~/.claude/skills/
npx skills add lgqyhm2010/loop-goal -g
```

`skills` रिपॉज़िटरी की जड़ में `SKILL.md` ढूँढता है और उसे (साथ ही
`templates/`) आपकी skills डायरेक्टरी में रख देता है। बिना इंटरैक्शन के
इंस्टॉल करने के लिए `-a claude-code -y` जोड़ें।

खुद हाथ से करना पसंद है? `SKILL.md` और `templates/` को
`.claude/skills/loop-goal/` में कॉपी करें।

इंस्टॉल होने के बाद, बस किसी लूपिंग या पूरा-होने-तक चलने वाले कार्य का वर्णन करें —
स्किल स्वयं सक्रिय हो जाती है (देखें "यह कब सक्रिय होती है")।

## समस्या

लंबे समय तक चलने वाले एजेंट कार्य तीन चुपचाप तरीकों से विफल होते हैं:

1. **खोई हुई प्रगति** — बातचीत का context सिकुड़ जाता है और
   एजेंट भूल जाता है कि उसने पहले क्या किया था।
2. **प्रदूषित context** — पुनरावृत्तियों (iterations) के दौरान टूल आउटपुट जमा होता जाता है,
   जिससे लंबे समय तक चलने में तर्क (reasoning) कमज़ोर पड़ता है।
3. **कोई निकास नहीं** — बिना लिखित रुकने की शर्त वाला लूप हमेशा चलता रहता है।

इनके समाधान सर्वविदित हैं (किसी फ़ाइल में checkpoint लें, प्रत्येक पुनरावृत्ति के लिए context अलग रखें,
निकास की शर्त लिख लें)। दिक्कत यह है कि ये इस बात पर निर्भर करते हैं कि एजेंट उन्हें करना *याद रखे* —
और लंबे समय तक चलने में अनुशासन बिखर जाता है। यह स्किल इन तीन समाधानों को लागू किए जाने
वाले नियमों में बदल देती है।

## यह क्या करती है

आह्वान (invoke) किए जाने पर, यह स्किल:

1. **मोड का पता लगाती है** — LOOP (समय-चालित, आवर्ती) बनाम GOAL
   (परिणाम-चालित, पूरा होने तक चलने वाला)।
2. **एक checkpoint फ़ाइल अनिवार्य करती है** — `.loopgoal/state.json` एकमात्र
   पुनर्प्राप्ति योग्य (recoverable) स्थिति रखती है; git commits इतिहास रखते हैं।
3. **छह नियम लागू करती है** — एक स्पष्ट निकास शर्त के साथ init करना, प्रत्येक पुनरावृत्ति को
   एक नए subagent में चलाना (context अलगाव), एक निश्चित क्रम में checkpoint लेना, resume पर सत्यापन करना,
   निर्णयों को लॉग करना, साफ़-सुथरे ढंग से बाहर निकलना।

यह **शुद्ध अनुशासन** है: यह कोई कोड नहीं लिखती, कोई कमांड नहीं चलाती, और
`/loop` या `/schedule` को रैप नहीं करती — यह केवल यह नियंत्रित करती है कि आप उन्हें *कैसे* चलाते हैं।

## यह कब सक्रिय होती है

"loop", "goal", "keep running", "run in a loop", "until X", "run autonomously" जैसे वाक्यांश —
या उनके चीनी समकक्ष "持续做", "每隔", "循环跑",
"直到…为止", "自主跑", "跑个 loop" — या एक स्पष्ट "use the loop-goal skill"।

## स्व-निहित (Self-contained)

किसी भी प्रोजेक्ट में काम करती है। यह केवल अंतर्निहित टूल (`Agent`, git)
और harness तंत्र (`/loop`, `ScheduleWakeup`) पर निर्भर है। superpowers
प्लगइन एक वैकल्पिक साथी है, कभी आवश्यकता नहीं।

  प्रोजेक्ट में कॉपी किया जाता है।
